# สิทธิ์ผู้ใช้งาน

| งาน | เจ้าของ | ผู้ดูแล | พนักงาน |
| --- | --- | --- | --- |
| ดูช่องจอด รับรถ คิดค่าจอด รับชำระเงิน ปล่อยรถ/บัตรหาย | ได้ | ได้ | ได้ |
| การจอง บัตรสมาชิก ประวัติรถ/ชำระเงิน และ Excel | ได้ | ได้ | ไม่ได้ |
| คำสั่งเปิดประตูด้วยตนเองผ่าน API | ได้ | ได้ | ไม่ได้ |
| Dashboard รายได้รวม, AI วิเคราะห์ภาพรวม, จำลองเวลา | ได้ | ไม่ได้ | ไม่ได้ |
| เอกสาร OOP | ได้ | ได้ | ไม่ได้ |

ผู้ดูแลเห็นค่าบริการรายรายการในประวัติและ Excel เพื่อดูแลงานประจำวัน แต่ไม่มีหน้า Dashboard รายได้รวม
พนักงานอ่าน API ตั๋วได้เฉพาะรถที่ยังไม่ออก และไม่เห็นรายได้รวมใน API สถานะ

บัญชีสำหรับโครงงาน: `owner / owner123`, `admin / admin123`, `staff01 / staff123`
(รวม `staff02` และ `staff03` ใช้รหัส `staff123`)

Java ตรวจ role จาก session ฝั่งเซิร์ฟเวอร์ทุกครั้งก่อนเรียก protected API และตอบ 403 เมื่อไม่มีสิทธิ์
การเปลี่ยน role ใน localStorage ไม่เปลี่ยนสิทธิ์ของ Java session
`UserRole` เป็น enum ที่รวมชื่อบทบาทและนโยบายเข้าถึง API ตามแนวคิด OOP

GitHub Pages เป็นเดโม: บัญชีและข้อมูลอยู่ในเบราว์เซอร์ การซ่อนเมนู/กันฟังก์ชันเป็นการสาธิตสิทธิ์
ผู้ใช้ที่แก้ JavaScript หรือ localStorage สามารถเปลี่ยนเดโมได้ จึงใช้ปกป้องข้อมูลจริงไม่ได้
การใช้งานจริงต้องรัน Java backend และเปลี่ยนระบบบัญชีตัวอย่างเป็นบัญชีที่จัดเก็บรหัสผ่านอย่างเหมาะสม
หน้านี้ยังไม่มีฟังก์ชันเพิ่มบัญชีหรือเปลี่ยนบทบาทผ่าน UI

ทดสอบหลัง compile: `python tests/test_roles.py bin` (ใช้ port 8080 และไดเรกทอรีข้อมูลชั่วคราว)
