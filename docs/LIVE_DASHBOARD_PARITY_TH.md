# เว็บหลักต้นฉบับบน AWS และการเชื่อมแพลตฟอร์ม

`dashboard.html` ใช้โครงหน้าและ CSS เดียวกับ `index.html` บน GitHub Pages แต่ใช้ `dashboard.js` ที่ติดต่อ `/api/platform/` เท่านั้น ไม่มี fallback สร้างตั๋วปลอมเมื่อเซิร์ฟเวอร์ไม่ตอบ และไม่ใช้ localStorage เป็นฐานข้อมูลบริษัท

| ส่วนงานต้นฉบับ | พฤติกรรมบน AWS |
|---|---|
| ผังช่องจอด / เลือกชั้น / รายละเอียดช่อง | อ่านผังที่เผยแพร่และรถที่กำลังจอดของลานที่เลือก กดช่องเพื่อรับรถหรือนำรถออก |
| จุดตรวจทางเข้า / แนะนำช่อง | ตรวจประเภทช่อง การจอง ช่องที่เลือก สิทธิ์สมาชิก และระยะทางในผัง ออกตั๋วจริงในฐานข้อมูล |
| ANPR / ไม้กั้น | คงภาพและลำดับจำลอง พร้อมป้ายระบุจำลอง ไม่มีการเปิดไม้กั้นจริงหรืออ้างว่าวิเคราะห์ภาพจริง |
| จุดชำระเงิน / ตั๋วหาย | เซิร์ฟเวอร์คำนวณราคาที่บันทึกตอนรถเข้า บวกค่าปรับตั๋วหาย 300 บาท รับชำระและออกใบเสร็จก่อนบันทึกรถออก |
| เงินสด / เงินทอน | ตรวจเงินที่รับและบันทึกเงินทอน รับชำระซ้ำไม่ได้ |
| PromptPay / บัตรเครดิต | บันทึกผลที่พนักงานยืนยันจากช่องทางภายนอกและเลขอ้างอิง ยังไม่เชื่อมธนาคารหรือ payment gateway ไม่เก็บข้อมูลบัตร/CVV |
| ประวัติตั๋วและบัญชี | แสดงรายการรับชำระและสถานะรถในลานเดียวกัน |
| ประวัติรถเข้าออก 3 เดือน / Excel | กรองวันที่และทะเบียน ส่งออกข้อมูลตามสิทธิ์ปัจจุบัน |
| จองล่วงหน้า | เลือกช่องหรือจัดช่องที่รองรับอัตโนมัติ บันทึกและยกเลิกการจองในแพลตฟอร์ม |
| บัตรสมาชิก | เก็บรหัส ชื่อ ทะเบียน ห้อง ประเภทและวันใช้สิทธิ์ สมาชิก VIP ได้ลำดับเลือกช่อง VIP ก่อนเมื่อว่าง |
| Dashboard รายได้ | รวมรายได้ตามวันรับชำระเวลาไทย สถานะพื้นที่ การจองและสมาชิก |
| OOP & SOLID | คงเมนูอธิบายสถาปัตยกรรมสำหรับการเรียน |
| AI / XAI / Heatmap / Copilot | แนะนำตามกฎ แสดงเหตุผล สถานะรถจอดจริง และสถิติรถเข้ารายชั่วโมงจากประวัติ ไม่มีค่าความแม่นยำหรือ CO2 ที่แต่งขึ้น ผู้ช่วยตอบจากข้อมูลลานที่เลือก |
| เร่งเวลา / รีเซ็ตเวลา | ใช้ได้เฉพาะลานตัวอย่างสำหรับ owner/super_admin รีเซ็ตได้เมื่อไม่มีรถค้างในลาน ไม่กระทบเวลาบริษัทจริง |

บัญชีลูกค้าและพนักงานถูกจำกัด tenant และ site ฝั่งเซิร์ฟเวอร์ เจ้าของแพลตฟอร์มเลือกบริษัทก่อนเข้าหน้าเว็บหลัก เปลี่ยนลานแล้วล้างตั๋วที่เลือก แชต และข้อมูลส่งออกเพื่อไม่ให้บริบทปะปน

API ใหม่: `POST /api/platform/quote` อ่านใบประเมินโดยตรวจสิทธิ์ลาน และคำสั่ง `reportLostTicket`, `recordPayment`, `sampleTime` การรับชำระใช้ revision และ expectedFee เพื่อไม่ยืนยันยอดเก่าหรือรับชำระซ้ำ เก็บวิธีชำระแบบ `MANUAL_*` อย่างชัดเจน

การทดสอบครอบคลุมการเข้า–ออกผ่านเว็บหลักร่วมกับตัวออกแบบ คำนวณราคา เงินไม่พอ ยอดเก่า การชำระซ้ำ ตั๋วหาย รายการชำระภายนอก การแยกบริษัท และหน้าจอมือถือ
