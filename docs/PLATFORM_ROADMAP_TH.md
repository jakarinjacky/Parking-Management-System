# งานต่อยอดหลังรวมแพลตฟอร์มเข้า main

สถานะปัจจุบันเป็น MVP รายละเอียดที่ใช้งานได้ดู PLATFORM_MVP_TH.md
การ merge ไม่ใช่การรับรองว่าพร้อมใช้ข้อมูลลูกค้าจริง ไม่มีการเปิดฟังก์ชันปลอมเพื่อรอพัฒนา

## P0 — ก่อนเปิดรับลูกค้าจริง

- [ ] ย้าย atomic JSON เป็น SQL พร้อม Repository interfaces และ transaction
  - ผ่านเมื่อข้อมูลหลายบริษัทไม่รั่ว, concurrent check-in ไม่ซ้ำ, rollback และ restore ทดสอบได้
- [ ] รวม ParkingService เดิมกับ tenant context และ migration แบบ dry-run
  - ผ่านเมื่อยอดเงิน/ตั๋ว/สมาชิกเดิมตรงก่อน–หลังย้าย และย้อนกลับได้โดยไม่ทำลายข้อมูล
- [ ] ปิดบัญชีสาธิตและ legacy demo API ใน production; HTTPS, reset password, session revocation
  - ผ่านเมื่อไม่มี default credential และทุก endpoint ทดสอบทั้งสิทธิ์/tenant/site
- [ ] Backup, restore drill, monitoring และ retention job
  - ผ่านเมื่อกู้ข้อมูลในเครื่องใหม่ได้ และกำหนดอายุ backup แยกจากข้อมูลประวัติ
- [ ] ตรวจ UI ด้วย browser และผู้ใช้จริง รวมการใช้งานบนโทรศัพท์/คีย์บอร์ด

## P1 — ลดขั้นตอนผู้ใช้งาน

- [ ] ตัวช่วยสร้างลานทีละขั้น: บริษัท → ประเภท → ผัง → ราคา → ทีมงาน → เปิดลาน
- [ ] สร้างช่องเป็นแถว, คัดลอกชิ้นส่วน, ตั้งเลขอัตโนมัติ และ autosave แบบร่าง
  - ห้าม autosave เผยแพร่เอง; ตรวจ revision conflict และเก็บ draft ที่ยังไม่ส่ง
- [ ] แบ่งโซนชัดเจน แม่แบบผังแต่ละธุรกิจแตกต่างกัน พร้อม preview ก่อนใช้
- [ ] เลือกช่องอัตโนมัติตามรถและการจอง พร้อมแสดงเหตุผลเมื่อไม่มีช่อง
- [ ] ใบเสร็จเงินสดและตรวจยอดก่อนยืนยัน; ห้ามสร้างรายการซ้ำเมื่อกดซ้ำ
- [ ] ค้นหาหลายลาน/ผู้ใช้ และปิดบัญชีหรือเปลี่ยนสิทธิ์พร้อม revoke session
- [ ] แสดงสถานะข้อผิดพลาดในฟอร์ม, focus ช่องที่ผิด, loading/disable ระหว่างส่งข้อมูล

## P2 — กฎธุรกิจเฉพาะสถานที่

- [ ] คอนโด: ลูกบ้าน–เลขห้อง, โควตารถ, อนุมัติผู้มาติดต่อ และวันหมดอายุสิทธิ์
- [ ] ห้าง: คูปองร้านค้า ตรวจการใช้ซ้ำ และยอดซื้อที่เชื่อถือได้
- [ ] โรงแรม: ผู้เข้าพัก–ห้องพัก–วันเข้าออก และ Valet พร้อมผู้รับผิดชอบรถ
- [ ] ราคา: แยกประเภทรถ รายวัน วันหยุด ส่วนลด และ snapshot กฎราคาที่ตั๋ว
- [ ] โลโก้ สี และข้อความต่อบริษัท; การอัปเดต template ไม่เขียนทับของลูกค้า

## P3 — อุปกรณ์และ Product

- [ ] Device Adapter / Gateway สำหรับกล้อง ESP32 ไม้กั้นและเซนเซอร์
  - เริ่ม LED bench test; command ID, acknowledgement, retry ที่ไม่เปิดซ้ำ, device credential
  - สถานะ Online ต้องมาจาก heartbeat จริง และมีเซนเซอร์/วิธีเปิดมือก่อนต่อไม้กั้น
- [ ] ถนนโค้ง/ขนาดจริง ทางลาดเชื่อมชั้น และตรวจแบบโดยผู้เชี่ยวชาญ
- [ ] Payment Gateway / subscription: signed webhook, idempotency, audit และแยก test/live
- [ ] Billing/ข้อจำกัดแพ็กเกจ/นโยบายข้อมูลส่วนบุคคล/ข้อตกลงบริการ

## สิ่งที่เตรียมแล้วในรอบรวม main

- ลิงก์แพลตฟอร์มจากหน้า login และหน้าลานเดิม
- เลือกเฉพาะช่องว่างที่เข้ากันกับรถในฟอร์มรับรถ
- ปุ่มคำสั่งในฟอร์มไม่ submit โดยไม่ตั้งใจ
- ช่วงวันที่ผิดไม่เปลี่ยนตัวกรองที่ใช้งานอยู่
- สคริปต์ทดลองรองรับ Bash เก่าบน macOS
- Deployment ตรวจ JavaScript และไฟล์แพลตฟอร์มก่อนเผยแพร่

Pages เผยแพร่ได้เฉพาะหน้า static/preview อ่านอย่างเดียว การใช้งานร่วมกันจริงต้องจัดหา
Java hosting และฐานข้อมูลก่อน ห้ามใส่รหัสผ่าน/secret ใน frontend หรือ GitHub repository
