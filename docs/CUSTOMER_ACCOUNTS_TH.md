# บัญชีเจ้าของแพลตฟอร์มและลูกค้า

ใช้ `/platform.html` เป็นทางเข้าสำหรับทุกบัญชี ระบบเลือกหน้าทำงานตามสิทธิ์จาก Session ฝั่งเซิร์ฟเวอร์ ไม่มีตัวเลือกให้ผู้ใช้ยกระดับสิทธิ์เอง

| บัญชี | ข้อมูลและงานที่เข้าถึง |
|---|---|
| เจ้าของแพลตฟอร์ม (`super_admin`) | ศูนย์ลูกค้า สร้างบริษัทพร้อมบัญชีเจ้าของ เลือกดูแลลูกค้าทีละบริษัท เปิด/ปิดบัญชีลูกค้า |
| เจ้าของบริษัทลูกค้า (`owner`) | ทุกลานในบริษัทของตน ออกแบบผัง ตั้งค่า ประวัติ และบัญชีผู้ดูแล/พนักงานของบริษัท |
| ผู้ดูแล (`admin`) | เฉพาะลานที่ได้รับมอบหมาย งานประจำวัน ประวัติ สมาชิก และอุปกรณ์ตามสิทธิ์เดิม |
| พนักงาน (`staff`) | เฉพาะลานที่ได้รับมอบหมายและรายการรถที่กำลังจอด งานรับรถ/นำรถออก |

## เพิ่มลูกค้าจริง

1. เข้าสู่ระบบด้วยบัญชีเจ้าของแพลตฟอร์ม
2. ในศูนย์ลูกค้า เลือก “เพิ่มลูกค้า / เจ้าของบริษัท”
3. ใส่ชื่อบริษัท ชื่อบัญชีที่ไม่ซ้ำ และรหัสผ่าน 12–128 ตัวอักษร
4. ส่งชื่อบัญชีและรหัสผ่านให้ลูกค้าผ่านช่องทางส่วนตัว ลูกค้าใช้ลิงก์ `/platform.html` และเปลี่ยนรหัสผ่านด้วยปุ่มในบัญชี
5. ลูกค้าสร้างลาน ออกแบบและเผยแพร่ผัง แล้วใช้เว็บหลัก `/dashboard.html` ด้วยบัญชีเดียวกัน
6. เจ้าของบริษัทเพิ่มผู้ดูแล/พนักงานใน “ทีมงานของบริษัท” และเลือกลานที่รับผิดชอบ

ไม่ต้องสร้างบัญชี AWS หรือฐานข้อมูลใหม่สำหรับลูกค้าแต่ละราย ข้อมูลแยกด้วย tenant ID และตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ บัญชีตัวอย่างมีเฉพาะโหมดสาธิต ห้ามใช้รหัสผ่านตัวอย่างกับลูกค้าจริง

## เจ้าของแพลตฟอร์มดูแลลูกค้า

เลือก “เข้าพื้นที่ลูกค้า” แล้วตรวจชื่อบริษัทที่แถบด้านบนก่อนทำงาน ลิงก์เว็บหลักจะส่งบริษัทที่เลือกไปด้วย กลับศูนย์ลูกค้าได้ด้วยปุ่มด้านบน การดำเนินการยังบันทึกชื่อบัญชีเจ้าของแพลตฟอร์มใน audit ไม่ได้สวมรอยเป็นลูกค้า

เจ้าของแพลตฟอร์มมีสิทธิ์ดูแลทุกบริษัทโดยตั้งใจ การแยกหน้าจอเป็นการเลือกบริบททำงาน ส่วนการป้องกันลูกค้าเห็นบริษัทอื่นทำใน API: กรองข้อมูลตามบัญชีและตรวจสิทธิ์การแก้ไขทุกครั้ง การแก้ URL, tenant ID, site ID หรือ role ใน request ไม่ให้สิทธิ์เพิ่มเติม

`GET /api/platform/state` รองรับ `X-Workspace-Tenant` สำหรับอ่านบริษัทเดียว และปฏิเสธบริษัทอื่นด้วย HTTP 403 สำหรับบัญชีลูกค้า ผู้ดูแลและพนักงานยังถูกจำกัดตามลานเดิม

## ตรวจรับหลัง Deploy

สร้างลูกค้า A และ B พร้อมลานคนละลาน ทดสอบคนละ browser profile: A ต้องไม่เห็นลาน ประวัติ ผู้ใช้ หรือ audit ของ B จากทั้งแพลตฟอร์มและเว็บหลัก เจ้าของแพลตฟอร์มต้องเข้าศูนย์ลูกค้าและเลือกบริษัทก่อนเปิดเว็บหลัก
